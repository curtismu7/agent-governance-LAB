# Safety

- Loopback bind only (`AGLAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped.
- Host header must be a loopback name; writes must be same-origin.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API in both modes. There is no worker thread and no child process. The provider calls, the gateway control calls and the connector polls are descriptions on `.example` hosts or rows in an in-memory log. Nothing is sent. The connector's "only dials out" is a property of the simulated log, shown as an illustration and counted from it.
- **The lab holds no credential for any cloud or provider.** There is no field that takes one: a body with an unknown key is refused (without naming the key). Credentials in the seeded data are names and rotation ages only.
- **Credential-shaped and personal-looking values the visitor types are masked (a heuristic: not every secret has a recognisable shape).** Detectors: common token shapes, plain-language password statements, URL userinfo, Authorization values, personal data (SSN, Luhn-checked card numbers, email, phone) and key-like runs; zero-width, soft-hyphen and bidi characters are deleted and the text is NFKC-normalised before masking, and masking happens before the cut to length. Free text (a reason, a comment, a tag value, a connection name) is cleaned on the way in (control and bidi characters removed, credential-shaped runs masked, then cut to length). Every JSON answer is masked again by the specific detectors as defence in depth. Values the engine stores that come from the visitor and are not free text (a pinned endpoint, a scanner id, a scanner location) are validated against a strict form and refused if they look credential-shaped (found by the echo test). Error messages are fixed text and never include input; field names are not echoed; ids in the path are never echoed. A test types every credential shape into every field, query, path, header and unknown key of every endpoint and searches every answer, the state afterwards and the process output for it.
- **Honest status codes.** A refusal keeps its 400, 403, 404 or 409. The state machines (propose, approve, execute; the campaign; the gateway; private network) refuse a wrong order, a duplicate, a stale approval and a wrong actor, and the refusals of authorization (not an administrator, self-approval, not the custodian) are written to the audit log with the acting user. **The acting user is self-declared in this lab (there is no sign-in), so "audited" here does not mean authenticated.**
- Every value used as an object key or lookup (agent id, proposal id, source, scope, gateway, runtime, target, session, vertical, scenario) is checked with a type test and `Object.hasOwn` or a list lookup; an unknown vertical or scenario falls back, anything else is refused. A missing or wrong-typed argument is a violation.
- Remediation support follows the deck: delete on twelve of thirteen sources, quarantine on exactly the seven the deck names (the deck says nine but names seven; the other two are not named, so the lab models seven). Any other source refuses quarantine with that reason.
- Writes are synchronous per engine, so a check and its change never interleave: parallel identical proposals give one, parallel approvals give one, parallel executes give one (tested over HTTP). A request that would break a cap is refused whole; nothing is dropped to make room.
- Input is bounded: bodies 32 KB, a reason 300 characters, a comment 200, 200 proposals, 500 audit entries (never dropped: new work is refused with 409 once fewer than 40 slots are free; refused attempts sit in a separate ring of 200 that counts what it drops), 5 campaigns, 10 connections, the newest 30 runs and 50 polls listed (older ones drop off the list and are counted), 20 injected failures, 6 tags per agent, 40 hops per answer. Workspaces are capped in count (500, new ones are refused at the cap, nothing is evicted) and age (1 hour idle).
- The server writes no file (a test greps for write calls). The one home-directory touch is reading the optional shared settings file (`~/Development/.env`, or `STANDALONE_ENV`) with `util.parseEnv`, taking only `AGL_LAB_MODE`. A bare `MODE` in it is ignored.
- Only `.example` and `.invalid` hosts appear in any shipped text (a doctor check scans the filled story in every vertical). The people, agents, accounts (000000000001-style fake ids), organizations and gateways are synthetic.
- Every product claim is labelled "Ping release claim, UNVERIFIED on our tenant" in the banner of every tab, in presenter mode too. Field names from the console swagger of 2026-10-31 are schema only; the lab says so wherever they appear, and tags each field as a deck claim, a swagger name, a lab reading or lab-invented.
